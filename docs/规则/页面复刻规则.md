# 页面复刻规则

面向：对照外部 ERP / 业务系统截图或原型，在本仓库中实现同等能力页面。

目标：**功能对齐对方，视觉与交互坚持本项目 Soft UI**，禁止照搬对方皮肤。

---

## 1. 核心原则

| 原则 | 说明 |
|------|------|
| **UI 用我们的** | 一律走本仓库 Soft UI（`UI 限制.md`、`src/styles/*`、Element Plus Soft 覆盖） |
| **功能对齐对方** | 字段、操作、流程、权限意图按对方实现；缺信息时先问再猜 |
| **组件复用优先** | 列表页优先 `PageList` / `PageSearch` / `PageTable`，不要另起一套布局 |
| **可切换真实接口** | 先 Mock，接口形状按真实 CRUD 设计，关掉 `USE_MOCK` 即可接后端 |

**禁止：**

- 复制对方的深色侧栏皮肤、主色、硬边框、密排 Ant 风表格样式到本系统
- 为「长得像对方」而破坏 Soft UI（圆角、柔和阴影、indigo 主色、间距）
- 无意义新建全局样式或绕过现有布局（MainLayout / Tags / 侧栏）

---

## 2. Soft UI 约束（复刻时必守）

- 页面容器：圆角卡片 + `var(--soft-shadow-lg)`，背景用 `--soft-bg` / `--soft-surface`
- 主色：`--soft-primary`（indigo 系），按钮 / Tag / Switch / 分页激活态统一
- 表格：走 `PageTable` + `element-soft.scss`；斑马纹用 `--soft-table-stripe`
- 夜间模式：改色只动 CSS 变量；**多选框边框不可依赖 `--el-border-color`（项目里常为 transparent）**，表格内复选框须保证深浅主题下都可见
- 间距：沿用当前后台密度（约 12px 级），不要突然改回对方超密排或超疏排

详细禁止项见根目录 `UI 限制.md`。

---

## 3. 功能复刻范围

从截图 / 说明中拆出并实现：

1. **工具栏**：新增、批量、导入/导出、刷新、列设置等——对方有的都要有入口；未做完的可 `ElMessage.info('xxx待开发')`，不可静默省略
2. **检索区**：对方可见的筛选项；无检索条时可按字段补常用筛选（名称、编码、状态等）
3. **表格列**：列名、含义、展示形态对齐（Tag、Switch、排序、固定操作列等）
4. **行操作**：编辑、删除、更多菜单项等；**操作列统一使用文字按钮**（`el-button` + `link`），禁止实心 / 描边小按钮
5. **弹窗 / 表单**：新增与编辑字段与校验
6. **批量能力**：至少支持批量删除；若对方有启用/停用等一并做

对方截图为空表时：仍实现完整交互，并用 **合理假数据** 填满演示。

**操作列约定：**

```vue
<el-table-column label="操作" width="140" fixed="right">
  <template #default="{ row }">
    <div class="table-actions">
      <el-button link type="primary" @click="openEdit(row)">编辑</el-button>
      <el-button link type="danger" @click="handleDelete(row)">删除</el-button>
    </div>
  </template>
</el-table-column>
```

- 主操作（编辑等）用 `link` + `type="primary"`
- 危险操作（删除）用 `link` + `type="danger"`
- 「更多」等下拉触发器同样用文字按钮，不用 `size="small"` 的填充按钮；多个操作包在 `.table-actions`（`inline-flex`）内保持同一行
- Soft UI 全局按钮阴影/位移**不作用于** `is-link` / `is-text`（已在 `element-soft.scss` 排除）
- 工具栏（新增 / 批量 / 导入导出）仍用常规按钮，本约定仅针对**表格操作列**

## 4. 工程落地约定

每个业务页建议按同一骨架新增：

```
src/views/<模块>/<Name>View.vue   # 页面
src/api/<name>.js                 # 请求封装
src/mock/<name>.js                # 假数据与 mock CRUD
src/router/menus.js               # 菜单（若尚未挂载）
src/router/index.js               # 路由（占位页改为真实 View）
src/utils/request.js              # 注册 mock 分支
```

约定：

- 路由 `meta.title` 与菜单标题一致
- Mock 列表支持分页 + 筛选；种子数据尽量信息完整（负责人、电话、地址等勿留空）
- 删除、批量删除需二次确认
- 启用类 Switch 失败时回滚本地状态

---

## 5. 菜单与信息架构

- 一级 / 二级菜单以用户提供的截图为准，挂到对应模块下
- 截图收起、看不清的子项：按同类业务对称补全，并在回复中说明假设
- 只补菜单与占位时：统一 `PlaceholderView`；开始复刻某页时再换真实 View

---

## 6. 交互与文案

- 文案使用简体中文，字段名与对方业务用语一致（如「废品仓」「行政等级」）
- 成功 / 失败用 `ElMessage`；危险操作用 `ElMessageBox.confirm`
- 「待开发」能力保留入口并提示，避免用户以为功能丢失

---

## 7. 验收清单（做完自检）

- [ ] 表格操作列均为文字按钮（`link`），非实心小按钮
- [ ] 视觉是 Soft UI，不是对方皮肤
- [ ] 对方截图中的列与主要按钮都有对应实现或明确占位提示
- [ ] 日间 / 夜间模式下表格多选框、斑马纹、文字对比度正常
- [ ] Mock 数据可演示，分页与筛选可用
- [ ] 菜单可进入，Tags / 面包屑标题正确
- [ ] 未引入与 Soft UI 冲突的全局样式

---

## 8. 与用户协作话术

开始复刻某模块时，默认理解为：

> 用我们自己的 Soft UI 复刻对方该页的**功能与信息结构**，不是 1:1 抄视觉。

若截图与 Soft UI 冲突（如对方强制深色侧栏样式），以本规则与 `UI 限制.md` 为准，功能仍按对方补齐。
