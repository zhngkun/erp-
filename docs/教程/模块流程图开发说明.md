# ERP 模块流程图开发说明

> 给后续开发 / Agent 阅读：如何为侧边栏父级菜单增加或定制流程图页。  
> LogicFlow 官方能力与 Agent Rules 见同目录 [`流程图说明书.md`](./流程图说明书.md)。

侧边栏**父级菜单**点击后，除展开子菜单外，还会打开该模块的流程图概览页（如 `/stock/overview`）。  
库存管理已定制；其他模块未定制时会按子菜单自动生成简易从左到右流程图。

## 已实现能力

| 能力 | 说明 |
|------|------|
| 父级点击开页 | `AppSidebar` 点击父级 → `/{module}/overview` |
| 路由 | 各业务模块已有 `overview` 子路由，`redirect` 指向 overview，`meta.isModuleRoot: true` |
| 画布 | LogicFlow 只读展示，长方形节点 + 箭头 + 沿箭头方向流动的虚线 |
| 节点点击 | `properties.path` 有值则 `router.push` 进业务页 |
| 定制 / 兜底 | `customFlowcharts` 有配置用定制图，否则 `buildAutoFlowchart` |

## 目录结构

```
src/components/flow/
  LogicFlowBoard.vue      # 画布封装（尺寸、主题、流动 CSS）
  registerFlowEdge.js     # 自定义节点 flow-rect、边 flow-edge

src/views/flow/
  ModuleFlowView.vue      # 所有模块共用的 overview 页面

src/config/flowcharts/
  helpers.js              # flowNode / flowEdge / defineFlowchart
  index.js                # 注册表 customFlowcharts + 自动生成
  stock.js                # 库存管理定制流程（范例）
  purchase.js             # 采购管理定制流程
  sales.js                # 销售管理定制流程
  cash.js                 # 往来现金定制流程
  production.js           # 生产管理定制流程
  quality.js              # 质量管理定制流程
```

已定制模块：`/stock`、`/purchase`、`/sales`、`/cash`、`/production`、`/quality`。
## 如何给新模块加定制流程图

以「采购管理」`/purchase` 为例，**一般只需改配置，不必改路由/侧边栏**（overview 路由已统一加好）。

### 1. 新建数据文件

复制库存范例，新建 `src/config/flowcharts/purchase.js`：

```js
import { defineFlowchart, flowEdge, flowNode } from './helpers'

// 建议：列 x 间隔约 240，行 y 间隔约 100；布局从左到右
const COL = { left: 140, mid: 380, right: 620 }

export const purchaseFlowchart = defineFlowchart(
  '采购管理流程',
  [
    flowNode({ id: 'plan', text: '采购计划', x: COL.left, y: 120, path: '/purchase/plan' }),
    flowNode({ id: 'order', text: '采购订单', x: COL.mid, y: 120, path: '/purchase/order' }),
    flowNode({ id: 'inbound', text: '采购入库', x: COL.right, y: 120, path: '/purchase/inbound' }),
    // path: null 表示仅展示、不可跳转
  ],
  [
    flowEdge({ id: 'e1', source: 'plan', target: 'order' }),
    flowEdge({ id: 'e2', source: 'order', target: 'inbound' }),
  ],
)
```

### 2. 登记到注册表

编辑 `src/config/flowcharts/index.js`：

```js
import { purchaseFlowchart } from './purchase'

export const customFlowcharts = {
  '/stock': stockFlowchart,
  '/purchase': purchaseFlowchart, // 新增
}
```

`key` 必须与 `src/router/menus.js` 里该父级的 `path` 一致（如 `/sales`、`/basic`）。

### 3. 验证

1. 登录后点击侧边栏对应父级（如「采购管理」）
2. 应打开「采购管理流程」页，连线带箭头且虚线沿箭头流动
3. 点击有 `path` 的节点应进入对应业务页

## 数据约定

### 节点 `flowNode`

| 字段 | 含义 |
|------|------|
| `id` | 唯一，边的 source/target 引用它 |
| `text` | 显示文案 |
| `x` / `y` | 中心坐标，**从左到右**排布 |
| `path` | 跳转路由；无跳转传 `null` |

实际渲染尺寸由画布统一为 **160×36** 长方形，无需在数据里写宽高。

### 边 `flowEdge` / `flowCurve`

| 方法 | 用途 |
|------|------|
| `flowEdge` | 同排水平折线 |
| `flowCurve` | 贝塞尔曲线；可传 `pointsList: [起点, 控制点1, 控制点2, 终点]` 精确绕行，避免多线重叠 |

### 连线入点约定（必须遵守）

从**上方业务节点**汇入**下方节点**时（如多条线汇入「应付事项」「应收事项」）：

1. **箭头终点必须落在目标节点的上边**（`y = 节点中心y - 半高`），不要从左/右侧插入。
2. 多条线汇入同一上边时，用不同的水平偏移错开入点，例如：偏左 `-52`、正中 `0`、偏右 `+52`。
3. 控制点也要错开，避免曲线重叠；参考 `purchase.js` / `sales.js`。

```js
// 上边入点示例（dx 为相对目标中心的左右偏移）
const halfH = 18 // 节点高 36 的一半
const topIn = (x, y, dx = 0) => ({ x: x + dx, y: y - halfH })

flowCurve({
  id: 'e-xxx-payable',
  source: 'xxx',
  target: 'payable',
  pointsList: [
    /* 起点 */,
    /* 控制点1 */,
    /* 控制点2 */,
    topIn(payable.x, payable.y, -36), // 必须在上边
  ],
})
```

### 同源向下分支布局（必须遵守）

同一节点向下分出多个并行业务节点时（如「销售出库」→「销货订单」「销项发票」）：

1. **优先排成同一行、左右排列**，不要上下叠成一列（竖排极易导致连线重叠）。
2. 各分支从源节点底边取**不同的水平出口**（如偏左 / 偏右），曲线分别落到各目标**上边**。
3. 与右侧其它汇聚区（如应收事项）在水平方向分区：左区放并行分支，右区放汇聚节点。

示例（`sales.js`）：

```
主行：销售订单 → 销售出库 → 销售退换 → …
支行：销货订单 | 销项发票          应收事项 → 收款单
         ↑          ↑                  ↑
      出库偏左出口  出库偏右出口     出库/退换/入库汇入上边
```

### 往来现金三行对称布局（必须遵守）

`cash.js` 按业务示意图做**左右对称、三行结构**，后续改动请贴近原图，不要改成单行或打乱簇归属：

```
上行：采购入库 | 采购退换 | 采购退货出库 | 支出单 || 销售退换 | 销售退货入库 | 收入单 | 销售出库
中行：进项发票        应付事项                          应收事项              销项发票
下行：              付款单                            收款单
```

1. **左簇（应付）**：采购入库、采购退换、采购退货出库、支出单 → 汇入「应付事项」→「付款单」；「进项发票」竖直落在「采购入库」正下方。
2. **右簇（应收）**：销售退换、销售退货入库、收入单、销售出库 → 汇入「应收事项」→「收款单」；「销项发票」竖直落在「销售出库」正下方。
3. **竖直短线**：上下对齐的父子（入库→进项、退换→应付、退货入库→应收、出库→销项、应付→付款、应收→收款）用近乎竖直的短曲线，控制点不要大弯。
4. **侧向汇入**：横向较远的源（退货出库/支出单 → 应付，退换/收入单/出库 → 应收）先下再横再上，终点仍落在目标**上边**，入点左右错开（如 `-48 / 0 / +36 / +56`），避免弧线交叉。
5. 列间距约 `175`，上→中行距大于中→下行距（参考 `ROW.top=110, mid=290, bottom=450`）。

### 生产管理三簇树形布局（必须遵守）

`production.js` 按业务示意图做**左 / 中 / 右三簇独立树**，簇间留白，不要串成一条主链：

```
左簇 MRP：独立需求 + 销售订单 → MRP计划 → 采购订单 | 生产订单 | 委外订单
中簇自制：独立需求 + 销售订单 → 生产订单 → 工序执行 | 完工入库 | 成品质检 | 领料出库 | 退料入库
                              工序执行 ↓ 工序汇报 ↓ 工序检验 ↓ 工序核算
右簇委外：销售订单 + 独立需求 → 委外订单 → 委外入库 | 成品质检 | 领料出库 | 退料入库
                              委外入库 ↓ 委外退换 ↓ 委外退库 ↓ 委外换入
```

1. **同名节点可重复出现**（如三簇各有「独立需求」「销售订单」），用不同 `id`，勿合并成一个节点。
2. 两源汇入 hub：上边入点左右错开（如 `-36` / `+36`）。
3. hub 向下多分支：同行左右排，底边出口水平错开，终点落在各子节点上边。
4. **竖链**（工序执行、委外入库下挂）保持与父列 x 对齐，用竖直短曲线，勿弯到旁支。

### 质量管理三列竖树布局（必须遵守）

`quality.js` 按业务示意图做**三列竖向分支 + 孤立节点**，不要改成横向主链：

```
左列：采购订单 → 来料质检 → 来料质检报告
                           ↘ 采购入库
中列：销售订单 → 出货质检 → 出货质检报告
                           ↘ 销售出库
孤立：质检装箱（无连线，夹在销售列与生产列之间）
右列：生产订单 → 首次质检报告
              ↘ 巡检报告
```

1. 每列竖直父子用短曲线，侧向子节点从上边入点落入。
2. 「质检装箱」仅展示可跳转，**不要**强行连线。
3. 三列水平分区，列间距约 `280`，行距约 `160`。

## 样式与动画注意（踩坑）

1. **节点尺寸**：LogicFlow 主题里的 `rect.width/height` **不会**改变模型尺寸；本项目在 `LogicFlowBoard` 里强制写入 `properties` + 自定义 `flow-rect`。
2. **流动方向**：不要依赖内置 `animationDirection`（SVG 上常不生效）。流动由 `LogicFlowBoard.vue` 中 CSS `@keyframes erp-flow-dash` 控制；`stroke-dashoffset` 往**负**方向 = 沿箭头流向。若方向反了，把 `to` 的偏移改成正值。
3. **箭头**：不要用 SVG `marker` 挂在虚线上（常不显示）。本项目在 `registerFlowEdge.js` 里对终点**手动画实心三角**；终点坐标必须贴目标节点边框外侧。
4. **keep-alive**：进入 overview 会重建画布，避免缓存旧实例导致样式不更新。

## 若某模块还没有 overview 路由

正常业务模块已批量加过。若新建顶级模块，在 `src/router/index.js` 中需要：

```js
{
  path: '/xxx',
  name: 'Xxx',
  component: Layout,
  redirect: '/xxx/overview',
  meta: { title: '某某管理', icon: '...', isModuleRoot: true },
  children: [
    {
      path: 'overview',
      name: 'XxxOverview',
      component: () => import('@/views/flow/ModuleFlowView.vue'),
      meta: { title: '某某管理流程' },
    },
    // ...业务子路由
  ],
}
```

侧边栏父级点击逻辑在 `AppSidebar.vue` 的 `onParentClick` → `getModuleOverviewPath`。
